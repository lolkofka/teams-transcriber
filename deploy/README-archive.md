# Общий архив пар

Задача зафиксирована в `TASK-shared-archive.txt` в корне проекта.

Развёрнутый сервис: https://bhpcubes.ru/transcriber/
Хост SSH: `bhpcubes` (`odin`). Исходники и Compose: `/home/lolkof/transcriber-archive`.
Данные HDD: `/hdd/transcriber-archive`. SQLite хранит текущие манифесты клиентов; исходные файлы лежат неизменными в `blobs` по SHA256. Совпадающий файл не загружается дважды. Никакого сжатия, серверной очистки или ограничения числа клиентов нет.

## Подключение клиентов

На настроенном Mac файл `archive-connection.json` содержит только адрес архива и общий ключ; он исключён из Git. Его можно передать одногруппникам вместе с программой, не передавая `journal.json`, `gui_settings.json`, Microsoft-профиль или другие личные файлы.

* Исходники / Windows: положить `archive-connection.json` рядом с приложением.
* Упакованная версия Mac: положить его в `~/Library/Application Support/TeamsTranscriber/`.
* Альтернатива: в настройках заполнить «Общий архив пар»: адрес и ключ.

Каждая установка автоматически получает собственный UUID в `archive-state.json`. Этот файл не копировать между клиентами. В верхней панели кнопка «Архив пар» открывает авторизованную страницу через одноразовый билет (60 секунд); основной ключ в URL не передаётся. Доступ также возможен по адресу сайта с ручным вводом ключа.

## Работа

Пока приложение открыто, каждые 30 секунд выполняется синхронизация. Текстовые файлы передаются снимками; активные/изменяющиеся аудиозаписи пропускаются до завершения записи. Файлы передаются кусками по 512 КиБ с продолжением и проверкой SHA256. После успешной загрузки всех файлов сервер подтверждает манифест; только после этого клиент запоминает разрешение на очистку.

Общий текст и исходные текстовые файлы всех клиентов автоматически скачиваются в `recordings/shared/<ID пары>/`. Аудио, картинки и презентации автоматически не скачиваются. Полный архив доступен на сайте в TAR без сжатия; он содержит общую версию и все исходные материалы клиентов.

Через 72 часа после конца пары нетекстовые файлы удаляются только из управляемой папки исходной записи клиента, если их текущее содержимое совпадает с подтверждённым сервером SHA256. Активная папка записи исключена. Без расписания используется время последнего материала. TXT/JSON/JSONL и другие текстовые форматы остаются. При закрытом приложении ничего не проверяется; cron/планировщик не используются. Сбой сервера откладывает синхронизацию и очистку.

Пара определяется по дате, времени начала по расписанию и нормализованному названию предмета. Архив рассчитан на общую группу с общим расписанием. Несовпадающие названия/время могут создать отдельные пары. Сопоставление реплик консервативное: близкие по времени похожие реплики разных клиентов объединяются с предпочтением более полного текста; отличающиеся варианты сохраняются в JSON. Неоднозначные фразы не удаляются. Презентации и слайды появятся в архиве, если клиент действительно собрал соответствующие файлы.

## Обслуживание

```sh
ssh bhpcubes
cd ~/transcriber-archive
docker compose -f compose.archive.yml ps
docker compose -f compose.archive.yml logs --tail 50
```

Ключ сервера хранится в `archive.env` (права 600). Для ротации сменить его, пересоздать контейнер и обновить подключение клиентов. Не публиковать ключи в Git.

Для обновления скопировать `archive_server.py`, `shared_archive.py`, `deploy/Dockerfile.archive`, `deploy/compose.archive.yml` в папку сервиса, затем:

```sh
docker compose -f compose.archive.yml up -d --build
```

Сервис доступен через существующий Traefik с HTTPS. Порт 8766 опубликован только на 127.0.0.1. Исходный обработчик Whisper на 8756 не изменён.
